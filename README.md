# llm_preference_classification-
Predicting human preferences between LLM responses with TF-IDF and multilingual DistilBERT. Kaggle score: 1.03740.
Предсказание человеческих предпочтений между ответами LLM с помощью TF-IDF и многоязычного DistilBERT. Результат на Kaggle: 1.03740.
# Предсказание предпочтений между ответами LLM

Проект на данных Kaggle LLM Classification Finetuning:
предсказание выбора пользователя между двумя ответами языковых моделей.

**Kaggle score:** 1.03740 — multiclass log loss.  
**Позиция:** 88 из 212 в текущей подвижной таблице на 11.09.26.

[Соревнование](https://www.kaggle.com/competitions/llm-classification-finetuning)

[Финальный Kaggle Notebook](https://www.kaggle.com/code/lyk1zm/04-transformer-submission)

## Задача

Вход:
- запрос пользователя;
- ответ модели A;
- ответ модели B.

Выход — вероятности трёх классов:
- предпочтение A;
- предпочтение B;
- ничья.

Основная метрика — multiclass log loss: меньше лучше.

## Подход

### Классические baseline

- Предсказание частот классов.
- Logistic Regression на признаках длины и оформления.
- TF-IDF + Logistic Regression с отдельными блоками признаков
  для запроса и двух ответов.
- Усреднение прогнозов исходной и переставленной пары — swap-TTA.

### Трансформер

Дообучен `distilbert/distilbert-base-multilingual-cased`
с классификационной головой на три класса.

Конфигурация:
- максимальная длина входа — 384 токена;
- запрос — до 96 токенов;
- каждый ответ — до 142 токенов;
- 2 эпохи;
- learning rate — 2e-5;
- физический batch size — 4;
- gradient accumulation — 8;
- эффективный batch size — 32;
- mixed precision FP16;
- обучение на одной GPU P100.

При обучении случайно переставлялись ответы A/B с соответствующей
заменой меток. Для инференса применено swap-TTA.

## Валидация

Использован первый fold из StratifiedGroupKFold с пятью разбиениями,
random_state=42. Группы определены по нормализованным последовательностям
запросов.

Одинаковые нормализованные запросы не пересекаются между обучением
и валидацией. Размер validation — 11 878 примеров.

TF-IDF и масштабирование признаков для validation-экспериментов
обучались только на train-части.

Названия моделей model_a/model_b не использовались как признаки,
поскольку они отсутствуют в тесте.

Это оценка на одном отложенном fold, а не полная пятикратная
кросс-валидация.

## Результаты

| Модель | Validation log loss ↓ | Kaggle score ↓ |
|---|---:|---:|
| Частоты классов | 1.097638 | — |
| Числовые признаки + Logistic Regression | 1.058017 | — |
| TF-IDF + Logistic Regression, C=0.3 | 1.056477 | — |
| TF-IDF + Logistic Regression, C=0.3 + swap-TTA | 1.034430 | — |
| Multilingual DistilBERT + swap-TTA | 1.034572 | 1.03740 |

Финальная отправка — multilingual DistilBERT со swap-TTA.

## Выводы

- Длина и оформление ответов содержат предсказательный сигнал.
- Swap-TTA улучшило validation log loss TF-IDF
  с 1.056477 до 1.034430.
- У трансформера на второй эпохе swap-TTA улучшило
  log loss с 1.040177 до 1.034572.
- Трансформер и TF-IDF показали практически одинаковое качество
  на выбранном разбиении.
- Утверждение о превосходстве трансформера над TF-IDF
  этими результатами не подтверждается.

## Запуск

Рекомендуемое окружение — Kaggle Notebooks.

1. Принять правила соревнования и подключить его данные.
2. Для baseline использовать CPU.
3. Для обучения трансформера включить GPU и интернет:
   интернет нужен для скачивания исходной модели.
4. Запустить ноутбук обучения и сохранить outputs с весами,
   токенизатором и конфигурацией.
5. Подключить outputs обучения к inference-ноутбуку.
6. Включить GPU, выключить интернет и запустить inference-ноутбук.
7. Результат — /kaggle/working/submission.csv.

При оценке Kaggle подставляет скрытый test.csv.
Инференс обрабатывает все строки, а не только открытый пример.

Данные и веса не включены в GitHub.
Доступ к данным — через страницу соревнования.
Артефакты модели — по ссылке на сохранённый Kaggle Notebook выше.

## Ограничения

- Гиперпараметры, checkpoint и применение TTA выбирались
  по одной validation-выборке.
- Группировка защищает от пересечения одинаковых нормализованных
  запросов, но не исключает пересечение семантически похожих диалогов.
- Длинные тексты обрезаются; модель может не видеть важную часть ответа.
- Реплики объединяются по полям, а не моделируются как полный диалог.
- Финальный трансформер обучен на train-части разбиения;
  переобучение на всех размеченных данных не выполнялось.
- Проект классифицирует предпочтения пользователей:
  это не RLHF и не дообучение генеративной LLM.
- Позиция в подвижной таблице может изменяться.
